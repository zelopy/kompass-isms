# KISA 클라우드 점검 항목 ISMS-P 매핑 검토표

기준일: 2026-10-16 (Prowler 비교 2026-10-17) · 이 파일이 원본이며 저장소(로컬·GitHub)에서만 관리함

## 검토 요청

KISA 클라우드 취약점 점검 항목(CA-01~CA-19)을 ISMS-P 통제항목에 대응시킨 초안이며, 실제 진단 업무 기준으로 맞는지 의견을 요청드림. 공식 대응표가 없어 문서 해석만으로는 확정하지 않고, 협의 결과를 반영한 뒤 확정할 예정임.

- 대상: KISA 클라우드 19개 항목, 자동 점검 룰 34개 (AWS 계정 읽기 전용 점검 도구 kompass-isms)
- 근거: ISMS-P 인증기준(고시 별표 7), 인증기준 안내서(2023.11)의 주요 확인사항·세부 설명
- 쓰임: 점검 보고서에서 KISA 항목별 결과 옆에 관련 ISMS-P 통제항목으로 표시함. 판정(양호·취약)에는 영향 없음
- 요청: 항목별 표의 "검토 의견" 칸에 동의·수정 필요·논의 필요를 고르고, 이견이 있으면 "의견" 칸에 적어 이 파일을 회신해 주시기 바람. 표 칸에 쓰기 어려운 의견은 회신 메일 본문으로도 받음. 특히 "협의할 쟁점" 절의 5건과 "참고: Prowler ISMS-P 대응표와 비교" 절의 반복되는 차이는 실무 관행을 기준으로 판단 부탁드림

## 매핑 원칙

원문에 근거 구절이 있는 통제항목만 후보로 올림. 아래 3가지는 초안 전체에 적용한 기준이라 항목별 검토 전에 확인 부탁드림.

1. **2.10.2 클라우드 보안은 19개 항목 모두에 매핑함.** 안내서 2.10.2(157쪽)는 보안 설정 기준 예시로 "인증, 암호화, 세션관리, 접근통제, 공개설정, 장기미사용 잠금, 로그기록, 백업 등"을 들고, 주의사항으로 "접근통제의 적절성, 인증 및 권한관리, 암호화… 보호조치가 모두 적용되어야 함"을 둠. KISA 클라우드 항목은 모두 이 범위에 들어간다고 봄.
2. **2.10.2 외에 해당 영역의 통제항목을 함께 매핑함.** 예: MFA는 2.5.3 사용자 인증, 로그 보관은 2.9.4 로그 및 접속기록 관리.
3. **점검 룰은 KISA 항목의 매핑을 따름.** 룰의 점검 범위가 항목보다 좁거나 달라 매핑을 빼거나 더한 경우는 "룰 단위 예외" 절에 따로 적음.

## 협의할 쟁점

해석에 따라 판단이 갈리는 5건이며, 실제 인증 심사에서 어느 통제항목의 증적으로 보는지를 기준으로 의견 부탁드림.

| # | 쟁점 | 현재 안 | 다른 선택지 | 협의 결과 |
| --- | --- | --- | --- | --- |
| 1 | 2.10.2를 19개 항목 전체에 매핑하는 것이 맞는가 | 전체 매핑 ("매핑 원칙" 1) | 안내서 2.10.2 예시에 직접 나오는 항목(관리자 권한·강화된 인증·공개설정·관리자 로그·알람)에만 매핑 | |
| 2 | 보안그룹(SG-001~003, CA-09)을 2.10.1 보안시스템 운영에 매핑하는가 | 매핑함. 보안그룹을 가상 방화벽으로 봄 (보안시스템 예시 "침입차단시스템(방화벽)", 154쪽) | 보안그룹은 클라우드 설정으로만 보고 2.6.1·2.10.2에만 매핑 | |
| 3 | SG-003(DB 포트 개방)을 2.6.4 데이터베이스 접근에 매핑하는가 | 매핑함. DB에 접근하는 서버·사용자를 식별·통제하는 것으로 봄 | 2.6.4는 DB 내부 접근통제(테이블·계정)로만 보고 제외 | |
| 4 | IAM-006(액세스 키 교체)을 2.5.3과 2.5.4 중 어디에 두는가 | 2.5.3 사용자 인증 (액세스 키를 인증수단으로 봄) | 2.5.4 "인증수단을 안전하게 적용하고 관리" (99쪽), 또는 2.10.2만 | |
| 5 | GuardDuty(GD-001)를 2.10.1 보안시스템 운영에도 매핑하는가 | 매핑하지 않음 (2.11.3, 2.10.2만) | 침입탐지시스템(IDS)으로 보고 2.10.1 추가 | |

## 참고: Prowler ISMS-P 대응표와 비교

오픈소스 점검 도구 Prowler의 ISMS-P 대응표 `kisa_isms_p_2023_aws`(메가존클라우드 기여, 101개 요구사항·546개 점검)와 비교한 결과임. 공식 대응표가 아니므로 매핑의 근거로 쓰지 않으며, 다른 실무자가 어떻게 매핑했는지 보는 참고 자료임 (2026-10-17 GitHub 기준).

- 비교 방법: 점검 룰마다 같은 설정을 보는 Prowler 점검을 이름·설명으로 짝지은 뒤, 그 점검이 속한 ISMS-P 요구사항을 모음. 점검 로직이 같은지는 확인하지 않음 (예: 비밀번호 최소 길이 기준이 다름)
- 결과: 대응 점검이 있는 룰 31개 중 10개는 같음, 21개는 다름. 대응 점검 없음: IAM-010·011(권한 보유 주체 현황), CT-002(추적 버킷 보존 기간), GD-002(GuardDuty 결과 알림)
